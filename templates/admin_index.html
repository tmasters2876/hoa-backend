Help & Reference

Browse & Filters

Filter clauses by keyword (searches clause_id, citation, document, plain summary, and full clause text), document, or tag. Results are paginated at 25 per page. Active filters persist across page turns.

Only clauses with status = approved are visible to residents via the Carrd chatbot. All statuses are visible here in the admin console.

Clause cards show a ⏳ Pending Approval badge when a change is queued but not yet approved. The live clause text remains unchanged until the pending change is approved.

Cards with an orange left border have a stale embedding — the clause text has changed since the embedding was last generated. Stale clauses are excluded from semantic (vector) search until regenerated. A yellow banner at the top of the page appears whenever stale clauses exist; click the link to filter to them directly.

Approval Workflow

Every clause change — add, edit, or delete — must be approved by a second admin before it takes effect in search results.

  • Submit for Approval — queues the change in Pending. The live clause is unchanged until approved.
  • ⚠ Self-approve (superusers only) — applies the change immediately, bypassing the two-person rule. Use only when no other admin is available. A warning is recorded in the audit log.
  • Deletions always require a second superuser to approve — self-approve is disabled for deletes.
  • The Pending (N) link in the header turns orange when items are waiting. Superusers can approve or reject from that page.

Source Verification

When a clause is submitted for approval, the system automatically downloads the linked Google Drive PDF and checks whether the clause text appears on the stated page using fuzzy text matching.

  • ✅ Verified — strong match found (≥ 80% similarity)
  • ⚠️ Partial — partial match found (50–79%)
  • ❌ Not Found — text not found on that page (< 50%)
  • ⏭ Skipped — PDF could not be accessed, or clause text was missing

Verification is advisory only — it informs the approver but never blocks submission or approval.

Three source fields are required on every clause: Citation, Page, and a Google Drive link (https://drive.google.com/…). Clauses missing any of these are rejected at submission.

Add Clause

Manually add a single clause. Citation, page, and a Google Drive source link are required. At least one of clause_text or plain_summary must be provided.

The embedding is not generated automatically on add — use Regenerate Embedding on the approved clause afterward so it appears in semantic search results.

Precedence Level controls result ranking when multiple clauses match a query. Higher values rank higher. Use 0 (default) for standard clauses; reserve higher values for overriding or primary governing documents.

Import CSV — Add

Bulk-inserts clauses from a .csv file. Download the blank template for the correct column layout. Each row must include citation, page, and a Google Drive link — rows missing any of these are skipped. CSV imports go live immediately (no approval step). Column rules:

  • At least one of clause_text or plain_summary must be non-empty per row
  • page and precedence_level must be whole numbers if provided
  • tags — comma-separated, e.g. fence, arc
  • match_source defaults to CSV Import if omitted
  • Columns not in the template are rejected; valid rows are inserted even if others in the same file fail

All imported clauses start with stale embeddings and will not appear in semantic search until regenerated. The yellow stale banner will appear after import as a reminder.

Import CSV — Delete

Permanently deletes every Supabase row whose clause_id matches a value in the uploaded file. There is no undo. Bulk CSV deletes go live immediately — no approval step, no second-person requirement. The CSV must contain a clause_id column; all other columns are ignored.

Embeddings

Each clause stores an embedding — a numeric vector used for semantic (meaning-based) search by the HOA chatbot. Keyword search is unaffected by embedding status.

  • Editing clause_text or plain_summary marks the embedding stale when the edit is approved and applied.
  • Stale clauses are excluded from vector search results until regenerated.
  • The yellow banner at the top of the page shows how many stale embeddings exist and links to a filtered view.
  • Use Regenerate Embedding on any clause to call OpenAI and refresh it. No approval required — takes effect immediately.
  • Model in use: {{ embedding_model }}

Search Test

Runs a live query using the same logic as the production chatbot — both semantic (vector) and keyword searches execute simultaneously against the Supabase match_clauses RPC. Results are displayed in two columns: Vector Matches and Keyword Matches.

Use this to verify a question surfaces the expected clauses before testing in the resident-facing frontend. Only approved clauses with valid embeddings appear in vector results.

Audit Log

Every action is recorded — clause adds, edits, deletes, approvals, rejections, embedding regenerations, user changes, password resets, and CSV imports. Accessible via the Audit Log link in the header (superusers only). Filter by user, action type, or date range. All timestamps are displayed in UTC.

User Management

Accessible via the Users link in the header.

  • Superusers (tmasters, cmasters) — can add, deactivate, delete, and reset passwords for other users. Superuser status cannot be granted or removed from the UI.
  • All users — can change their own password from the Users page via Change Password.
  • You cannot deactivate or delete your own account from the admin UI.
  • Login sessions expire after 8 hours. Login and logout events are recorded in the activity log.
